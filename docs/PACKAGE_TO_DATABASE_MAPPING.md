## Datasets researched but not projected

The research exists in Git and no table reads it. This is the gap between
"researched" and "visible", and it is larger than the gap the import closes.

| Dataset | Rows | Would enable |
|---|---:|---|

| `Package007/district_scheme_mapping.csv` | 305 | **scheme → district edges (currently 0)** |

| `Package006/career_paths.csv` | 15 | learning order |
| `Package006/ai_skill_mapping.csv` | 45 | AI-augmentation detail |

`district_scheme_mapping.csv` is the most consequential line in this table. It
holds **305 district↔scheme pairs** and the graph builder does not read it, which
is why there are **zero** scheme→district edges and why two recommendation rules
(`RS2-VIA_DISTRICT`, `RI3-VIA_DISTRICT`) are structurally dead. Recorded in
`RELATIONSHIP_RECOVERY_REPORT.md`; unchanged since.

## Does anything execute the import automatically?

**Before this sprint: no.** There was no `.github/` directory. `scripts/run_sync.sh`
existed and required a human.

**After this sprint: yes.** `.github/workflows/knowledge-sync.yml` runs it on
every merge touching `packages/`, `knowledge_graph/`, `knowledge_sync/`,
`governance/vocabulary/` or `scripts/`; weekly; and on demand. It fails its
preflight with an explicit message until three repository secrets exist.
